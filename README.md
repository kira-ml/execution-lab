# Execution & Market-Impact Lab

[![ci](https://github.com/kira-ml/execution-lab/actions/workflows/ci.yml/badge.svg)](https://github.com/kira-ml/execution-lab/actions/workflows/ci.yml)

**Status:** **ACTIVE — v0.1.0 built and tested.**  
**Project type:** Applied system, not a research paper.  
**Part of:** the four-project portfolio: Robustfolio → Epistemic DRO → **Execution Lab** → Risk Cockpit.

> **Decision it supports:** given a target portfolio and a rebalance, which execution schedule minimizes expected cost plus timing risk — and does the strategy ranking survive realistic costs?

This is a transparent, deliberately small execution-cost laboratory. It does **not** connect to a broker, route orders, or claim tradable alpha. It asks what a 10-bps backtest assumption hides.

---

## What it does

1. **Decomposes cost** into half-spread, commission, square-root market impact, and timing risk.
2. **Compares schedules**: immediate, TWAP, VWAP, and POV, across horizons.
3. **Integrates with a portfolio**: target weights → trades → costs → net returns.
4. **Shows ranking sensitivity**: does the strategy ordering change with order size, impact coefficient `k`, and AUM?
5. **Reports a range, not a point estimate**, because `k` is not identified from daily OHLCV.

The demo runs on a checked-in **synthetic** six-ETF panel. A user with licensed data can point the CLI at a long-format CSV; the repository never redistributes vendor data.

## Quickstart

```bash
pip install -e .
execution-lab demo --out results/demo
```

Then open `results/demo/report.md`. The command writes:

- `order_schedule_comparison.csv` — one order under every schedule;
- `schedule_frontier.csv` / `optimal_by_risk_aversion.csv` — the cost/risk trade-off;
- `ranking.csv` — strategy × cost-model net Sharpe;
- `k_sensitivity.csv` / `break_even_k.csv` — how much impact kills the edge;
- `aum_sensitivity.csv` — capacity stress;
- figures and a `manifest.json` with the panel hash.

Price one order:

```bash
execution-lab simulate --ticker VNQ --shares 250000 --price 90 \
  --adv 2000000 --sigma 0.014 --spread-bps 6 --schedule vwap --horizon 5
```

Compare schedules:

```bash
execution-lab sensitivity --ticker VNQ --shares 250000 --price 90 \
  --adv 2000000 --sigma 0.014 --spread-bps 6 --compare
```

Fit `k` from observed execution costs:

```bash
execution-lab calibrate --observations costs.csv --bootstrap
```

## Headline demo results

These are **synthetic-data results**, generated by `execution-lab demo`. They illustrate the method; they are not evidence about real ETFs.

For a 10%-of-ADV order in the least-liquid demo asset:

| Schedule | Expected cost (bps) | Timing risk (bps) | Objective at λ = 0.05 |
|---|---:|---:|---:|
| VWAP 5-day | 16.12 | 221.41 | **27.19** |
| TWAP 5-day | 16.39 | 221.63 | 27.47 |
| VWAP 3-day | 19.65 | 171.26 | 28.21 |
| Immediate | 31.12 | 0.00 | 31.12 |

The trade-off is the point: spreading lowers impact but adds timing risk against the arrival price. At a higher risk aversion (λ ≥ 0.10), immediate execution wins; at λ = 0, the 5-day VWAP wins.

The synthetic demo ranking is **stable** across cost models at $250M AUM because the cost differences are smaller than the gross Sharpe gaps. Capacity still binds: momentum's net Sharpe falls from 0.23 at $25M to −0.07 at $50B, while the low-turnover strategies survive. That is a more honest capacity statement than a forced rank flip.

The **local real-data check** (12 ETFs, 2013–2026, aggregate results only) does show a rank change: equal weight overtakes momentum once realistic spread and impact are charged. The naive 10-bps assumption is not conservative for a wide-spread ETF; the VNQ half-spread proxy alone is about 20 bps. Momentum's break-even `k` against zero Sharpe is 5.38, and its net Sharpe crosses zero around $28.8B AUM in that sample. See [`docs/REAL_DATA_CHECK.md`](docs/REAL_DATA_CHECK.md).

See [`docs/RESULTS.md`](docs/RESULTS.md) for the full synthetic tables and [`docs/METHOD.md`](docs/METHOD.md) for the equations.

## Method in one screen

For an order of `Q` shares at price `P`, with daily volatility `σ`, average daily volume `V`, and quoted spread `s`:

```
expected_cost = s/2 + commission + impact
impact_bps    = k · σ_bps · participation^exponent
```

The schedule changes **participation per slice** and therefore impact. Timing risk is the standard deviation of the implementation shortfall under a zero-drift random walk:

```
timing_risk_bps = σ_bps · sqrt(x' M x),    M_ij = min(t_i, t_j)
```

where `x` are slice fractions and `t` are execution times in days. Immediate execution has `t = 0`, so its timing risk is zero by construction.

| Schedule | Fractions | Volume used | What it is |
|---|---|---|---|
| Immediate | one slice | one day | cross the spread now |
| TWAP | equal per time bin | U-shaped intraday profile | equal time |
| VWAP | proportional to volume | proportional to volume | constant participation |
| POV | VWAP over an endogenous horizon | target participation | horizon set by order size |

The model is a stylised approximation. It is useful for ranking and sensitivity, not for predicting a particular fill. See [`docs/LIMITATIONS.md`](docs/LIMITATIONS.md).

## Data

- **Demo:** synthetic, deterministic, seed `20261108`, six stylised ETF archetypes, 2018-01-02 to 2024-12-30. No vendor data.
- **Local real data:** the CLI accepts any long-format CSV with `date,ticker,open,high,low,close,volume[,spread_bps]`. A local validation on the owner's licensed ETF snapshot can be recorded in `docs/REAL_DATA_CHECK.md` without committing the raw data.
- **Spread proxy:** observed `spread_bps` if supplied; otherwise the Corwin-Schultz high-low estimator with a floor and cap.
- **No order-book data.** The model does not claim order-book realism.

See [`docs/DATA_LICENSES.md`](docs/DATA_LICENSES.md).
